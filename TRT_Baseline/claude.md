# TRT Baseline — L1+L2 Implementation Plan

## Context

The current AdaExplore baseline (`results/timing/RTX-4090-D/baseline_time_torch.json`)
times the KernelBench reference modules under `torch.eager`. Agents beat that by virtue
of any compilation, so it doesn't measure "is the agent's kernel actually good." The
fix is to compare against TensorRT FP32 on the same GPU — the strongest stock inference
engine the 4090 can produce — by exporting each `Model` to ONNX, building a TRT engine,
and timing it the same way the torch baseline is timed.

Scope is narrowed on this pass to **level1 (100 files) + level2 (100 files)** — 200
total. No engine cache, no timing cache: every run rebuilds
from scratch.

A generic loop — *dynamic import → seed → instantiate → `torch.onnx.export(...)` →
optional `onnxsim`* — covers all 200 with no per-file skip list. Failures (if any) get
logged and the manifest records them; downstream stages just record
`"status": "onnx_export_failed"`.

## Pipeline shape

Three stages, three files. Order matches the user's revision:

```
TRT_Baseline/
├── claude.md                     (this plan)
├── config.yaml                   (NEW — fixed TRT + run params)
├── convertONNX/
│   ├── convert_all.py            (NEW — single ONNX exporter)
│   ├── onnx_out/                 (gitignored — generated artifacts)
│   │   ├── level1/<n>_<name>.onnx
│   │   └── level2/<n>_<name>.onnx
│   └── manifest.json             (per-file export status)
├── engines/                      (gitignored — generated by trtexec)
│   ├── level1/<n>_<name>.plan
│   ├── level1/<n>_<name>.times.json
│   ├── level2/<n>_<name>.plan
│   └── level2/<n>_<name>.times.json
├── build_and_time.py             (NEW — trtexec driver + numeric check)
└── torchImport/                  (kept empty for now; future fallback)
```

Final timings land in `results/timing/RTX-4090-D/baseline_time_trt.json`.

### Stage 1 — `TRT_Baseline/config.yaml`

Single source of truth. The build script reads it; nothing is hard-coded.

```yaml
hardware: RTX-4090-D
device: cuda:0
gpu_id: 0

precision: fp32
tf32: false                    # honest FP32 — matches torch baseline contract

workspace:
  mode: max_capped
  cap_bytes: 17179869184       # 16 GB cap to avoid OOM on 24 GB cards

builder:
  optimization_level: 5
  tactic_sources: [CUBLAS, CUBLAS_LT, CUDNN, EDGE_MASK_CONVOLUTIONS]
  prefer_precision_constraints: false

shapes:
  mode: static                 # no optimization profile (min/opt/max)

onnx:
  opset_version: 17
  simplify: true
  random_seed: 42              # for nn.Parameter(randn) reproducibility

timing:
  warmup: 20                   # ignored by Stage 3 (trtexec uses ms, not iters) — kept for reference / future Python-runtime callers
  warmup_ms: 200               # trtexec --warmUp value (default = trtexec's own default)
  trials: 200
  use_cuda_graphs: auto        # on iff engine has no shape-changing ops

caching:
  engine_cache: false          # per user fix — fresh build each run
  timing_cache: false          # no persisted TRT timing cache either

levels: [1, 2]                 # only L1+L2 in this pass
dataset_root: datasets/KernelBench
output_path: results/timing/RTX-4090-D/baseline_time_trt.json
tolerance:
  atol: 5.0e-2                 # matches src/eval.py
  rtol: 5.0e-2
```

### Stage 2 — `TRT_Baseline/convertONNX/convert_all.py`

Single generic exporter. Reads `config.yaml` for `random_seed`, `opset_version`,
`simplify`, `levels`, `dataset_root`. Walks each level dir, for every `*.py`:

1. `importlib.util.spec_from_file_location` to load the file fresh (no module cache
   collisions — multiple files all define `class Model`).
2. `torch.manual_seed(cfg.onnx.random_seed)` *before* `Model(...)` — required for
   the 33 files with `nn.Parameter(torch.randn(...))`.
3. `model = M.Model(*M.get_init_inputs()).cuda().eval()` inside `torch.no_grad()`.
4. `inputs = tuple(t.cuda() for t in M.get_inputs())` — passes the 14% multi-input
   files automatically.
5. `torch.onnx.export(model, inputs, onnx_path, opset_version=17,
   input_names=['in_0', 'in_1', ...], output_names=['out_0', ...],
   dynamic_axes=None, do_constant_folding=True)`.
6. If `simplify`: `onnxsim.simplify(...)`, overwrite.
7. Record `{level, file, status, onnx_path, error}` into `manifest.json`.

Output tree mirrors the source: `onnx_out/level1/1_Square_matrix_multiplication_.onnx`
etc. Errors don't abort the loop — they land in the manifest and propagate as
`onnx_export_failed` to the final JSON.

CLI shape: `python TRT_Baseline/convertONNX/convert_all.py --config TRT_Baseline/config.yaml`.

### Stage 3 — `TRT_Baseline/build_and_time.py`

Reads `config.yaml` + `manifest.json`. Stage 3 drives **`trtexec`** (the
TensorRT CLI shipped at `/opt/tensorrt/bin/trtexec`, v10.x) as a
subprocess for build + timing, and only uses the Python TRT runtime for
the post-build numeric-parity check.

For every ONNX with `manifest.status == ok`:

#### 3a. Build + time via `trtexec` subprocess

Construct the command from `config.yaml`:

```
trtexec
  --onnx={onnx_path}
  --saveEngine=TRT_Baseline/engines/level{N}/{stem}.plan
  --noTF32                          # cfg.tf32 == false
  --memPoolSize=workspace:{cap_MiB} # min(free_mem, cfg.workspace.cap_bytes) // (1<<20)
  --builderOptimizationLevel=5      # cfg.builder.optimization_level
  --tacticSources=+CUBLAS,+CUBLAS_LT,+CUDNN,+EDGE_MASK_CONVOLUTIONS
  --warmUp={cfg.timing.warmup_ms}   # ms; default 200
  --iterations={cfg.timing.trials}  # 200
  --avgRuns=1                       # report per-iter, not bucket-averaged
  --useCudaGraph                    # iff cfg.timing.use_cuda_graphs resolves to true
  --useSpinWait                     # tighter latency measurement
  --exportTimes=TRT_Baseline/engines/level{N}/{stem}.times.json
```

- No `--timingCacheFile` — `cfg.caching.timing_cache: false`.
- No `--fp16/--bf16/--int8/--fp8` — pure FP32.
- Static shapes — no `--minShapes/--optShapes/--maxShapes`.
- `subprocess.run(cmd, capture_output=True, timeout=...)`. Non-zero exit
  → record `status: trt_build_failed`, attach last 40 lines of stderr to
  the manifest, skip to next file.
- Engines are kept on disk under `TRT_Baseline/engines/level{N}/` (gitignored).
  Fresh build each run is preserved by *not* passing `--timingCacheFile`
  and by `convert_all.py` overwriting ONNX inputs each run; the `.plan`
  files are retained for postmortem and for the numeric check in 3b.

#### 3b. Numeric verification (Python TRT runtime, post-build)

`trtexec` cannot diff against PyTorch, so the parity check is done in
Python after the engine file lands:

1. Re-run the dynamic-import idiom from Stage 2 to instantiate the
   torch `Model`. `torch.manual_seed(cfg.onnx.random_seed)` *before*
   `Model(...)` so randn-initialized parameters match the export.
2. Move to CUDA, `eval()`, `torch.no_grad()`, run once on
   `M.get_inputs()` to get the torch reference output.
3. Deserialize the saved `.plan` with `tensorrt.Runtime`, allocate
   device buffers via `cuda.mem_alloc`, bind tensor addresses with
   `set_tensor_address(...)`, copy inputs in, run
   `execute_async_v3(stream)`, copy outputs out.
4. `torch.allclose(trt_out, torch_out, atol=5e-2, rtol=5e-2)` per
   output tensor (matches `src/eval.py`). Mismatch →
   `status: numeric_mismatch`; skip the timing entry but keep the
   `.plan` and `times.json` for postmortem.

#### 3c. Parse `--exportTimes` JSON + write output

`trtexec --exportTimes` writes a JSON list, one entry per measured
iteration, each with `latencyMs` (compute + H2D + D2H wallclock) and
`computeMs` (kernel-only). Stage 3 reads `latencyMs` — it matches the
end-to-end semantics of the torch eager `cudaEvent` baseline.

Compute `mean / std / min / max` over the array, set
`num_trials = len(array)`, append/update an entry under `level{N}` in
`results/timing/RTX-4090-D/baseline_time_trt.json` keyed by source
filename, using the schema already documented below in this file.

CLI: `python TRT_Baseline/build_and_time.py --config TRT_Baseline/config.yaml [--filter level{N}/{id}]`.

## Files to create (NEW)

| Path | Purpose |
|---|---|
| `TRT_Baseline/config.yaml` | Fixed TRT + run parameters |
| `TRT_Baseline/convertONNX/convert_all.py` | Single ONNX exporter for all L1+L2 |
| `TRT_Baseline/build_and_time.py` | trtexec driver + numeric check + JSON write |
| `TRT_Baseline/.gitignore` | Ignore `convertONNX/onnx_out/`, `engines/`, `__pycache__/` |

## Patterns to reuse

- **Dynamic-import idiom** for KernelBench files: see the inline timing snippet
  used in the project notes (`importlib.util.spec_from_file_location`).
- **Tolerance values** (`atol=rtol=5e-2`): same as `src/eval.py`.
- **Output JSON schema**: mirror `results/timing/RTX-4090-D/baseline_time_torch.json`
  (`mean/std/min/max/num_trials/hardware/device`), add provenance fields.
- **Test-list format**: `config/test_list/test_list_2.txt` shows the
  `<level> <id>` line convention if the user later wants to drive smoke runs from
  the same lists agents use.

## Output schema

Same shape as `baseline_time_torch.json`, plus a few provenance fields:

```json
{
  "level2": {
    "1_Conv2D_ReLU_BiasAdd.py": {
      "mean": 0.0,
      "std": 0.0,
      "min": 0.0,
      "max": 0.0,
      "num_trials": 200,
      "hardware": "NVIDIA GeForce RTX 4090 D",
      "device": "cuda:0",
      "engine": "trt-10.x",
      "path": "convertONNX",
      "tf32": false,
      "workspace_bytes": 17179869184,
      "status": "ok"
    }
  }
}
```

`status` ∈ `ok | onnx_export_failed | trt_build_failed | numeric_mismatch`. Failed
entries still appear so the agent harness can decide whether to fall back to the
torch baseline for that problem.

## Locked decisions

| Question | Decision |
|---|---|
| TF32 | **OFF** (honest FP32) |
| Failed-export policy | **Skip + record `status: onnx_export_failed`**, sweep continues |
| Output filename | `baseline_time_trt.json` (sibling to `baseline_time_torch.json`) |
| Engine cache | **Off** — fresh build each run |
| Timing cache | **Off** — no persisted TRT builder timing cache |
| Levels in this pass | **L1 + L2 only** (200 files) |
| Hardware label | `RTX-4090-D` (reuses existing dir) |
| Stage 3 driver | **`trtexec` CLI** (Python only for numeric verification + JSON aggregation) |

## Expected gotchas

- **Random parameters.** 33 L2 modules use `nn.Parameter(torch.randn(...))` —
  must `torch.manual_seed(42)` *before* `Model(...)` so weights are reproducible.

## Verification (end-to-end)

1. Run `python TRT_Baseline/convertONNX/convert_all.py --config TRT_Baseline/config.yaml`
   on a smoke subset first (e.g., level2/1 only — add a `--filter` CLI flag, or
   point `dataset_root` at a temp dir with one file).
2. Confirm `manifest.json` shows `status: ok` and the `.onnx` file exists.
3. Run `python TRT_Baseline/build_and_time.py --config TRT_Baseline/config.yaml`
   (shells out to `trtexec` per ONNX for build + timing).
4. Inspect `results/timing/RTX-4090-D/baseline_time_trt.json` — should have one
   entry with positive mean/std and `"status": "ok"`. Confirm
   `TRT_Baseline/engines/level{N}/<stem>.plan` and `<stem>.times.json`
   were written.
5. Spot-check numeric parity vs. torch eager on the same file (`atol=rtol=5e-2`).
6. Sanity-check by replaying the engine alone:
   `trtexec --loadEngine=TRT_Baseline/engines/level{N}/<stem>.plan --iterations=200`
   should reproduce a similar mean (validates the `--exportTimes` parser).
7. Only then drop the smoke filter and sweep all 200 L1+L2 files.

Reproducibility check: rerun stage 3 in a fresh process; per-problem `mean` should
agree within ~5% (`std/mean` target).
